# Steering Templates Documentation

## Overview

Steering templates are Markdown files that define the structure and content for project documentation files generated by the HiveForge Steering System. These templates help AI agents understand project structure, conventions, and architecture.

## Canonical Template Location

**IMPORTANT:** The canonical (authoritative) location for all steering templates is:

```
hiveforge-power/hiveforge/templates/steering/
```

### Why hiveforge-power/ is Canonical

1. **Template Variants**: The `hiveforge-power/` location contains project-type-specific template variants (e.g., `tech-stack.cli_tool.md`, `api-standards.mcp_server.md`) that don't exist in `src/`
2. **Active Development**: All new template features and variants are developed in `hiveforge-power/`
3. **MCP Integration**: The HiveForge Power (MCP server) directly uses templates from this location

## Template Synchronization

### Dual Locations

For backwards compatibility, base templates are maintained in two locations:

- **Canonical**: `hiveforge-power/hiveforge/templates/steering/` (source of truth)
- **Legacy**: `src/hiveforge/templates/steering/` (synchronized copy)

### Base Templates

The following base templates must be kept synchronized between both locations:

1. `api-standards.md`
2. `architecture.md`
3. `conventions.md`
4. `db-standards.md`
5. `project-vision.md`
6. `qa-standards.md`
7. `tech-stack.md`
8. `ui-standards.md`

### Template Variants (Canonical Location Only)

The following template variants exist **only** in the canonical location:

- `api-standards.mcp_server.md` - MCP server-specific API standards
- `tech-stack.cli_tool.md` - CLI tool-specific tech stack
- `tech-stack.web_app.md` - Web application-specific tech stack

## Making Template Changes

### Step 1: Edit Canonical Location

Always make changes in the canonical location first:

```bash
# Edit template in canonical location
vim hiveforge-power/hiveforge/templates/steering/tech-stack.md
```

### Step 2: Sync to Legacy Location

After editing a base template, sync it to the legacy location:

```bash
# Copy from canonical to legacy
cp hiveforge-power/hiveforge/templates/steering/tech-stack.md \
   src/hiveforge/templates/steering/tech-stack.md
```

### Step 3: Verify Synchronization

Run the template sync verification script:

```bash
python hiveforge-power/scripts/check_template_sync.py
```

Expected output:
```
Checking template synchronization...
  ✓ IDENTICAL: api-standards.md
  ✓ IDENTICAL: architecture.md
  ✓ IDENTICAL: conventions.md
  ✓ IDENTICAL: db-standards.md
  ✓ IDENTICAL: project-vision.md
  ✓ IDENTICAL: qa-standards.md
  ✓ IDENTICAL: tech-stack.md
  ✓ IDENTICAL: ui-standards.md

SUCCESS: All 8 base templates are in sync!
```

## CI/CD Integration

### Automated Sync Checking

The CI pipeline automatically verifies template synchronization on every push and pull request:

```yaml
# .github/workflows/ci.yml
jobs:
  template-sync-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check template synchronization
        run: python hiveforge-power/scripts/check_template_sync.py
```

### CI Failure Handling

If templates diverge, the CI will fail with:

```
ERROR: Template directories are out of sync!
Canonical location: hiveforge-power/hiveforge/templates/steering/
Please sync changes from canonical location to src/
```

To fix:
1. Copy the changed template from `hiveforge-power/` to `src/`
2. Commit the synchronized files
3. Push to trigger CI re-run

## Template Structure

### Frontmatter

Templates include YAML frontmatter for metadata:

```yaml
---
name: tech-stack
description: Technology stack and dependencies
category: technical
priority: high
---
```

### Placeholders

Templates use `{placeholder}` syntax for content that should be filled:

```markdown
### Backend
- **Language:** {Python 3.11|Node.js 18|Go 1.21|...}
- **Framework:** {FastAPI|Express|Gin|...}
```

### Template Variants

Project-type-specific variants use naming convention: `{template_name}.{project_type}.md`

Examples:
- `tech-stack.cli_tool.md` - For CLI tools (no frontend section)
- `tech-stack.web_app.md` - For web apps (includes frontend)
- `api-standards.mcp_server.md` - For MCP servers (MCP tool standards)

## Template Resolution

The template loader resolves templates in this order:

1. **Project-type variant**: `{template}.{project_type}.md` (e.g., `tech-stack.cli_tool.md`)
2. **Base template**: `{template}.md` (e.g., `tech-stack.md`)

Example:
```python
# For a CLI tool project
# Resolves to: tech-stack.cli_tool.md (if exists)
# Falls back to: tech-stack.md
```

## Best Practices

### DO:
- ✅ Always edit templates in canonical location first
- ✅ Run sync verification script before committing
- ✅ Create project-type variants for specialized needs
- ✅ Use descriptive placeholder text
- ✅ Include frontmatter metadata

### DON'T:
- ❌ Edit templates in `src/` directly
- ❌ Commit unsynchronized templates
- ❌ Create variants in `src/` location
- ❌ Use empty placeholders like `{...}`
- ❌ Skip CI checks

## Troubleshooting

### Templates Out of Sync

**Problem**: CI fails with "Template directories are out of sync"

**Solution**:
```bash
# Copy all base templates from canonical to legacy
for file in api-standards.md architecture.md conventions.md db-standards.md \
            project-vision.md qa-standards.md tech-stack.md ui-standards.md; do
  cp hiveforge-power/hiveforge/templates/steering/$file \
     src/hiveforge/templates/steering/$file
done

# Verify sync
python hiveforge-power/scripts/check_template_sync.py
```

### Template Not Found

**Problem**: `FileNotFoundError: Template {name} not found`

**Solution**:
1. Check if template exists in canonical location
2. Verify template name matches exactly (case-sensitive)
3. For variants, ensure project type is correct

### Wrong Template Loaded

**Problem**: Base template loaded instead of variant

**Solution**:
1. Verify variant file exists: `{template}.{project_type}.md`
2. Check project type classification is correct
3. Ensure variant is in canonical location only

## Migration Guide

### From src/ to hiveforge-power/

If you have custom templates in `src/`, migrate them:

1. **Copy to canonical location**:
   ```bash
   cp src/hiveforge/templates/steering/custom.md \
      hiveforge-power/hiveforge/templates/steering/custom.md
   ```

2. **Update references** in code to use canonical location

3. **Remove from src/** (optional, for cleanup):
   ```bash
   rm src/hiveforge/templates/steering/custom.md
   ```
